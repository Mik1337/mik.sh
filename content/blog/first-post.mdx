## Why the rewrite?

I've been through Jekyll, Eleventy, and Next.js iterations of this site. Each time I'd hardcode content into components, which meant changing the design meant rewriting everything.

This time it's different.

## The architecture

- **Content is config.** Every piece of text, every work entry, every social link lives in typed TypeScript objects under `content/`. No strings in components.
- **Themes replace components.** Each theme is a complete set of pages and components that consume the same content data. Switch themes at runtime — same blog, different visual language.
- **Framer Motion for delight.** Shared motion primitives (`fade-in`, `stagger-children`, `text-reveal`) that every theme can compose.
- **Blog via MDX.** Write posts in Markdown with frontmatter. Syntax highlighting via rehype-pretty-code. All statically exported for GitHub Pages.

```typescript
// Every theme exports the same interface
interface ThemeManifest {
  Layout: React.FC;
  HomePage: React.FC;
  BlogList: React.FC;
  BlogPost: React.FC;
}

// Switching is instant
<ThemeProvider themes={{ default, onepiece }}>
  <App />
</ThemeProvider>
```
